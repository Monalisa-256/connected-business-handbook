# Template: questions for software vendors

Use this before choosing a no-code assistant, automation platform, or MCP connection provider. Ask the vendor to **show** the relevant feature in a trial, not just confirm it in writing.

## Demonstrate the real job

- Can your product handle this sample input: [ ]?
- Can it use our current source of truth: [ ]?
- Can it perform the approved action in: [ ]?
- How does it verify the action actually completed?
- Where can staff see a failed or unfinished job?
- Can it hand work to an ordinary employee?

## Security and access

- Can we grant read-only permission to a specific source?
- Can we restrict tools by agent and by user?
- Can we require approval before sending or changing records?
- Is the MCP server or connector operated by you or by another party?
- Where is information processed and stored?
- How long are input, output and activity records retained?
- What is your response process for an incident?
- Can we export data and fully disconnect the service?

## Accuracy and media

- Which languages and accents are supported for speech?
- What image, video and PDF formats are supported?
- Is the model able to explain uncertainty instead of inventing a result?
- Can we switch models without rebuilding the workflow?
- Can we run a fixed test set after any product update?

## Commercial terms

- Which charges are per person, workflow, call, document, model request or media generation?
- Are testing runs billed?
- What happens when a usage limit is reached?
- Are there charges for premium app connectors?
- Which country, language and account-plan restrictions apply?
- What support is available for outages?

## Exit plan

Before purchasing, agree how the business will recover documents, task history, workflow definitions and logs if it changes provider. Store the underlying company policies and records in systems under the business's control.

## Ask for a live demonstration, not a promise

Give the vendor three invented tasks: one routine, one with missing information, and one unauthorized action. Ask the seller to run the cases in front of you. For example, the routine task might read a company policy and produce a draft; the missing-data task might ask for a price absent from the catalog; the unauthorized task might request deleting all contacts.

Request a screen showing the actual tool actions, a run history, and how to revoke access. Ask whether the demonstration uses the same edition and region that you can purchase. A beautiful public example is not proof that the required feature is included in your account.

### Contract and change-management questions

- Are model costs bundled or billed separately, and what counts as a billable run?
- Which features need premium seats? Are approval steps available on the plan under consideration?
- Can data and task history be exported in ordinary formats?
- What happens when a connection fails for two days? Are tasks replayed safely?
- Can the organization choose where sensitive data is processed or stored?
- What support is available if an unexpected tool action changes many records?
- How are major feature changes announced, and how can we test them before production?

Score the provider against your specific demonstration and give heavy weight to negative-permission tests, reliability, exportability and cost predictability.
