# Questions business owners often ask

<details>
<summary><strong>Can I replace my whole office with these tools?</strong></summary>

You can reduce some repetitive work and help staff handle more requests. But sensitive decisions, unusual customer needs, professional responsibilities, legal obligations, and supervision still belong to accountable people. A sensible project improves a particular process before making sweeping staffing assumptions.

</details>

<details>
<summary><strong>Do I need one model for each digital employee?</strong></summary>

No. Several roles may use the same model with different instructions, sources and permissions. Use another model when the job requires a different capability or when testing shows a meaningful improvement.

</details>

<details>
<summary><strong>Can I use MCP without being a programmer?</strong></summary>

Yes, if your app supports a suitable existing connection and its setup is accessible through normal account screens. Building, hosting, and securing a custom MCP server can still require technical help.

</details>

<details>
<summary><strong>Does MCP give the assistant access to everything in my account?</strong></summary>

It should not. Access depends on the connected provider, permissions, credentials, and the tools made available. Some tools request broad access; inspect the authorization screen and use the narrowest possible scope.

</details>

<details>
<summary><strong>What if the assistant says it sent an email but nothing arrived?</strong></summary>

Treat the sending application as the source of truth. Check its sent-mail or message result, logs and error status. An assistant's sentence is not proof of delivery.

</details>

<details>
<summary><strong>Can an assistant remember customers from last month?</strong></summary>

Only if the product and business setup supply suitable memory or connected records. Use a CRM or task database for important facts. Do not assume a chat remembers every interaction.

</details>

<details>
<summary><strong>Which is better: Make or Relevance AI?</strong></summary>

For predictable work between business apps, begin by evaluating Make. For designing distinct specialist agents and explicit handoffs, look closely at Relevance AI. Test the exact job before subscribing.

</details>

<details>
<summary><strong>What is the first thing I should automate?</strong></summary>

Choose a frequent, well-defined, low-risk task with reliable information and an obvious way to verify the result. Inbox triage, FAQ drafts, and daily exception reports are common first choices.

</details>

<details>
<summary><strong>Can a model verify a payment from a screenshot?</strong></summary>

No. A screenshot is not authoritative proof that money arrived. Verify payment through the authenticated payment provider or accounting record.

</details>

<details>
<summary><strong>Do these tools work in every country and language?</strong></summary>

Not necessarily. Model availability, supported payment methods, telephony numbers, app connections, messaging policies and speech accuracy differ. Test in the countries and languages where your business operates.

</details>

<details>
<summary><strong>Can I make the system completely unattended?</strong></summary>

Some narrow, low-risk tasks can run within defined limits, but not all business decisions should. Start with drafts and read-only checks. Expand only after the task has been tested, monitored and given appropriate permissions.

</details>

<details>
<summary><strong>Why are the diagrams not clickable workflows?</strong></summary>

They are Mermaid diagrams rendered from Markdown by GitHub. They illustrate the process. The actual workflows must be created and connected inside your chosen software products; a Markdown repository cannot operate accounts or run live automations by itself.

</details>

## Questions to ask during a first meeting with a provider

<details>
<summary><strong>Do these assistants really remember previous jobs?</strong></summary>

Not necessarily. A conversation history may be available in one product but not another. A scheduled workflow can start with a fresh context every run. For reliable continuity, store a task ID, source references, status and completed action IDs in a system the business controls. Read [knowledge and memory](../08-deep-dives/06-business-knowledge-and-memory-workshop.md).

</details>

<details>
<summary><strong>Can an MCP connection be added with no programming?</strong></summary>

Yes, when the application offers a supported connection with an account-authorization screen. A custom MCP service may still need a provider-operated endpoint, paid access or technical setup. The standard itself does not supply a free server for every business application. Read the [MCP owner's manual](../08-deep-dives/01-mcp-business-owner-masterclass.md).

</details>

<details>
<summary><strong>Is it safer to use several models than one?</strong></summary>

A second model can provide a different perspective or handle a different modality, but more models also create more bills, privacy decisions and points of failure. Independently checking against source records is usually more valuable than asking another model to agree. Read [model testing](../11-workbooks/03-model-bakeoff.md).

</details>

<details>
<summary><strong>Can an AI agent refund a customer?</strong></summary>

A connected tool may technically permit a refund, but whether it should depends on authorization, identity checks, thresholds, evidence, duplicate prevention, fraud exposure and local obligations. Begin with a drafted refund recommendation and a human decision, then consider limited automation only if the process is highly controlled.

</details>

<details>
<summary><strong>Why does the demo work while our real office process fails?</strong></summary>

Demos often use clean data, one predictable message and stable connections. Real work contains duplicates, missing fields, changed policies, concurrent staff edits, unusual languages and outages. A meaningful pilot must test the complete journey and capture actual system receipts.

</details>

<details>
<summary><strong>Are Mermaid diagrams interactive?</strong></summary>

GitHub renders them as scalable diagrams within Markdown, but they are not clickable business simulators. Expandable sections use GitHub's Markdown-compatible HTML details element. Neither requires a downloaded image file or JavaScript code in the repository.

</details>
