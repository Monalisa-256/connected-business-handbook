# Publication and release checklist

This repository can be published with the GitHub website; programming tools are not required. The steps below are for the person maintaining the handbook.

- [ ] Decide whether this is a public general reference or a private company manual.
- [ ] Remove private business examples, personal information, access tokens and internal URLs.
- [ ] Confirm that the README is in the repository root, not one folder too deep.
- [ ] Upload the Markdown files with their numbered folder structure intact.
- [ ] Open the [diagram atlas](10-diagram-atlas/README.md) and check that large Mermaid diagrams render.
- [ ] Click through the major paths in the README and verify relative links.
- [ ] Check the source register against the current official product documentation.
- [ ] Verify any plan, pricing or country limitations before recommending a vendor.
- [ ] Decide on a copyright notice and license before inviting public reuse. No license is assumed here.
- [ ] Identify who may approve factual revisions and who will review time-sensitive chapters.
- [ ] Keep completed customer-specific worksheets in a private operating system, not in this example repository.

If a public GitHub reader reports that a feature differs from the book, collect the product name, current account plan, date and official reference before updating the affected chapter.
